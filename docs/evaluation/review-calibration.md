## Method

Each run drives the real repository on a fresh in-memory SQLite database for the synthetic persona `mdm-wong`: reset, then sixty simulated days, each advanced with an authored reading (steps as a fraction of the person's anchored reference, wear-time and rain) that replaces the simulation event's own. When a day opens a review case, the simulated coordinator reviews it that day through the same repository call the API uses; in the `fixed_rule` and `agent` arms any proposal then open is approved that day. The policy ladder, the absolute floor, the shadow check, the calibrator and its guardrail, the put-backs and the audited skips are the product's own. Every episode carries a latent label Care+ never sees: whether it is review-worthy, and by which day it should reach a coordinator. Delays are measured against the `starting_setting` arm for the same profile and sequence. The weekly proposal cap counts wall-clock time, so the sequences are authored to stay under it and the report counts any skip it causes.

Arms:

- `starting_setting` -- No proposal is ever approved: the starting review setting (40% below for three valid-wear days) stays live throughout.
- `fixed_rule` -- LLM off. The deterministic fixed rule proposes; the simulated coordinator approves every open proposal on the day of the review that produced it.
- `agent` -- LLM on with a scripted stand-in (NOT A MODEL) as the calibrator's transport; the simulated coordinator approves every open proposal on the day of the review that produced it. No network call is made.

Simulated coordinators:

- `accurate` -- Not a concern for benign episodes; agrees with review-worthy ones, and says a case should have reached them sooner only when it opened after the episode's latest acceptable day.
- `dismissive` -- Resolves every case as not a concern, including review-worthy ones.
- `over_cautious` -- Agrees with every case and says every one should have reached them sooner.
